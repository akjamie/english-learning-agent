## 🛠️ Lingo English v4.5.1 — AI Content Reliability Hotfix

### 1. No More Silent Canned Fallbacks for AI Curriculum
- AI evaluation questions (DIAGNOSIS) and the weekly plan (PLAN) are now **strict content**: when the LLM truly fails, the app surfaces a visible error with a Retry button instead of silently swapping in canned/offline content that looks AI-generated. Verified on-device: a failed diagnosis shows "Could not load your quiz" + Retry, never the fallback 🍎 Apple set.

### 2. Real Token Budget for Plan Generation
- PLAN requests previously used the shared 500-token default; glm-5.2 would spend it all on reasoning (empty content) and the fallback model would be cut off mid-JSON. PLAN now uses the DIAGNOSIS budget (1500 tokens), and an invalid plan response is rejected instead of caching a broken empty plan.

### 3. Timeouts That Match the Task
- PLAN/DIAGNOSIS now allow up to 90s per model call (previously a flat 15s coroutine timeout), and the OkHttp socket read timeout was raised 15s → 120s so the socket outlives the per-task budget. Reasoning-heavy models routinely take 20-40s on 10-question diagnosis JSON; the old hard 15s killed both primary and fallback calls.

### 4. Voice on Eval Questions
- The diagnosis listen/repeat buttons now speak through the configured cloud TTS channel (seed-tts-2.0 plan API with MP3 cache), with a fallback notice when cloud TTS is unavailable. Verified on the LingoTest emulator: the 🔈 button fetches and plays real audio.

### Verification
- Full unit test suite green (EXIT=0); on-simulator runs with the live token confirmed AI diagnosis questions load, the AI weekly plan renders (theme + per-day rationale annotations), and eval-question voice plays.
